## // Before you start

This week is about connecting a page to an API, and the API **comes ready**: you will not write it, only run it, test it and, in Module 09, add one piece of configuration. This module shows how to get it up and how to get to know it well before calling it from the page. Knowing the other side of the conversation prevents half of all integration problems.

## // The problem: you cannot integrate with what you do not know

To call an API, the page needs to know which addresses exist, which methods they accept, what data they expect and what responses they return. Finding that out **through the page** mixes two problems (the API and the JavaScript) and makes every error ambiguous. The fix is to test the API first, on its own, with the tools that have no CORS: Swagger and `curl`.

## // Getting the API up

The API lives in the material's `example/api-inicial` folder. Copy it to `projeto-fullstack/api`. You will need **Python 3.10 or newer**. Check the version in a terminal:

| System | Command |
|---|---|
| macOS and Linux | `python3 --version` |
| Windows | `py --version` |

The API was tested with Python 3.12.3. If the version is lower than 3.10, install a newer one from `python.org` before continuing.

### > 1. The virtual environment

Inside the `projeto-fullstack/api` folder, create a virtual environment, an isolated folder for the project's libraries, and activate it:

| Step | macOS and Linux | Windows |
|---|---|---|
| Create | `python3 -m venv .venv` | `py -m venv .venv` |
| Activate | `source .venv/bin/activate` | `.venv\Scripts\activate` |

When the environment is active, the terminal shows `(.venv)` at the start of the line.

> **ABOUT WINDOWS**
> This week's commands were run on **Linux** and were **not tested on Windows or macOS**. Creating the environment follows the Python documentation. If activation fails in PowerShell because of a security policy on the computer, use the Command Prompt (`cmd`).

### > 2. Installing FastAPI

The folder's `requirements.txt` lists what the API needs, in one line:

```
fastapi[standard]>=0.143,<0.144
```

```
pip install -r requirements.txt
```

The version range is **pinned** on purpose: FastAPI is a `0.x` library, and new versions can change behaviours.

### > 3. Starting the API

```
fastapi dev main.py
```

The terminal shows something like this (the start of the output; the icons the program draws were omitted here):

```
Starting FastAPI in development mode
Using import string: main:app
Server started at http://127.0.0.1:8000
Documentation at http://127.0.0.1:8000/docs
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
```

The API lives at `http://127.0.0.1:8000`. The `dev` mode reloads by itself when you save a file, and serves **only your computer**. To stop the server, press **Ctrl+C**. Leave this terminal open: the API has to keep running.

> **ALWAYS USE FASTAPI DEV, NOT FASTAPI RUN**
> The `fastapi run` command serves on `0.0.0.0`, that is, **your whole network**, and this API has no access control whatsoever. While you are studying, use only `dev`.

## // The API's map

Open `http://127.0.0.1:8000/docs`. This is the interactive documentation (Swagger), generated by FastAPI itself. It needs the internet to load its visual files: without a connection, the page opens blank, even though the API works. The routes:

| Method | Route | What it does | Success | Possible errors |
|---|---|---|---|---|
| `GET` | `/materias` | Lists the six subjects | `200` | |
| `GET` | `/grupos` | Lists the groups, with search and pagination | `200` | `422` (invalid parameter) |
| `GET` | `/grupos/{grupo_id}` | Fetches one group | `200` | `404`, `422` |
| `POST` | `/grupos` | Creates a group | `201` | `409`, `422` |
| `PATCH` | `/grupos/{grupo_id}` | Changes only some fields | `200` | `404`, `409`, `422` |
| `DELETE` | `/grupos/{grupo_id}` | Deletes a group | `204` | `404` |

`GET /grupos` accepts four optional parameters, at the end of the URL:

| Parameter | What it does | Default and limits |
|---|---|---|
| `q` | Searches part of the name, case-insensitively | No filter |
| `materia_id` | Only the groups of that subject | No filter |
| `limit` | How many groups to return | 10, between 1 and 100 |
| `offset` | How many groups to skip | 0 |

The response already comes **sorted by name** and carries the `x-total-count` header, with the total number of groups matching the filters, before the page is cut. The data lives **in memory**: every time the API restarts (including when you save a file), it goes back to its initial state.

## // The shape of the data

A group, as the API returns it:

```json
{
  "nome_grupo": "Modelagem e SQL",
  "materia_id": 3,
  "max_participantes": 8,
  "descricao": "Encontros online às terças e aos sábados",
  "grupo_id": 3,
  "criado_em": "2026-09-03T12:00:00Z"
}
```

A subject:

```json
{"materia_id": 1, "nome": "Cálculo I", "codigo": "MAT101"}
```

And the rules the API enforces, which the page will have to respect and handle:

| Field | Rule | If it is violated |
|---|---|---|
| `nome_grupo` | Between 3 and 60 characters | `422` |
| `materia_id` | Must exist | `422` |
| `max_participantes` | Between 2 and 50 (default 10) | `422` |
| `descricao` | Up to 200 characters, optional | `422` |
| Repeated name in the same subject | Case-insensitive | `409` |

In the `PATCH`, the `nome_grupo`, `materia_id` and `max_participantes` fields **do not accept** `null`: omit the field to leave it unchanged. Only `descricao` accepts `null`, which clears it.

## // Testing the API on its own

Before any JavaScript, run three tests:

**With Swagger:** at `/docs`, expand `GET /grupos`, click **Try it out** and then **Execute**. Read the `200` code, the body and the `x-total-count` header.

**From the command line, a listing:**

```
curl -i "http://127.0.0.1:8000/grupos?limit=2"
```

**From the command line, a creation:**

```
curl -i -X POST http://127.0.0.1:8000/grupos \
  -H "Content-Type: application/json" \
  -d '{"nome_grupo": "Cálculo II na prática", "materia_id": 1}'
```

The response is a `201 Created`, with the `location: /grupos/7` header and the created group in the body. Restart the API (or save `main.py`) to bring the data back to its initial state.

## // Good example × bad example

**Bad example**: discovering the API through the page:

```
"I will write the whole page and see what the API returns."
```

Every error becomes a mystery: was it the API, the JavaScript, CORS? You lose hours finding out something a `curl` would have shown in a second.

**Good example**: getting to know the API first, with a `curl` for each route:

```
1. List, fetch, create, change and delete with curl.
2. Trigger each error on purpose (404, 409, 422) and read the response.
3. Only then write the JavaScript, knowing what to expect.
```

## // Common mistakes

| Mistake | Why it happens | How to fix it |
|---|---|---|
| `fastapi: command not found` | The virtual environment is not active | Activate the environment (`(.venv)` in the terminal) |
| `Address already in use` | Something else is already using port 8000 | Stop the other server, or use `fastapi dev main.py --port 8001` (and adjust the page's address) |
| Swagger opens blank | No internet to load the visual files | Connect and reload |
| The groups you created are gone | The API restarted, and the data lives in memory | That is expected: recreate the data |
| `422` when testing the `POST` with `curl` | `-H "Content-Type: application/json"` was missing | Add the header |
| `ModuleNotFoundError` on startup | The command was run outside the API's folder | Enter the folder that holds `main.py` |

## // Checkpoint

> **BEFORE MOVING ON, THINK ABOUT THIS**
> Why is it better to test the API with `curl` and Swagger **before** writing the JavaScript that calls it?

Answer: because `curl` and Swagger do not have the browser's restrictions (such as CORS), and they isolate the API from the page. If `curl` works, you know the API is right, and any error that shows up later is in the page or in the connection between the two. Without that test, a single symptom ("the list does not show up") can have five different causes.
